01核心讲解

👩‍💻 聊天是「说」，Agent 是「做」

聊天 AI 像电话那头的顾问：它告诉你怎么做，但手还是你的。Agent 像坐在你旁边的实习生：你说「把这份表整理一下」，它会打开文件、动手改、做完给你看。

这类能自己使用工具、分多步完成目标的 AI，在 AI 圈有个名字，叫 Agent（智能体）。它不是一个魔法按钮，而是一个会规划、会试错的执行者。

OpenCode 就是这样一个 Agent 工具：它能在你的文件夹里读写文件、运行命令、跑测试。这次演示，我们让它在空文件夹里做一个猜数字小游戏。

🔄 它的工作循环：目标 → 拆步 → 动手 → 看结果 → 修正

你说：「做一个猜数字游戏，能双击玩，做完自己测一遍。」它会把任务拆开：建 index.html、写界面、写逻辑、跑测试、发现按钮没反应、修好、再测。

这就像实习生干活：先列个计划，做一步，看一眼结果，不对就改。区别是它动作很快，而且不会嫌你改需求。

但它也会犯错。下面的真实回放里，它第一版就漏了一个 id，自测全过，真正在浏览器里点却报错。这个细节很重要。

🎯 你要给它三样东西：目标、边界、验收

目标：做什么、给谁用、什么算完成。比如「单文件、双击能玩、1–100、有提示和重新开始」。

边界：只能改哪个文件夹、哪些文件不能动、不要联网、不要装东西。第一次合作，从空文件夹或小项目开始。

验收：做完自己测一遍，把测试结果给我看。最好再加一句：「不确定的地方标出来，不要猜。」

三样说全，它才像「你带的实习生」，而不是「一个很会说话的搜索框」。

🔐 权限越大，越要盯着

Agent 能写文件、跑命令、访问网络，这些权限用好了是效率，用不好是风险。

四条底线：重要文件先备份；看清它要执行的命令再同意；不把密码、身份证、客户资料给它；不确定的操作，先让它解释，再决定。

这不是「信不信任 AI」的问题，是「权限要匹配任务」。让它在一个小文件夹里折腾，比让它在你整个电脑上自由发挥安全得多。

🧪 真实回放：它也会犯错，你要验收

这次真实运行里，OpenCode 写完第一版，用 Node 跑了 30 项断言，全过。但我没有就此打住，而是自己打开浏览器点了一遍——结果报错：找不到 #status 元素。

我把这句报错原样丢回同一个会话。它定位到：页面上「已猜 0 次」的 div 只写了 class，没写 id，所以脚本取到 null。改一行，复测通过。

AI 的自测，不等于你的验收。它能检查逻辑，但真正的使用场景，只有你会遇到。你要亲手点一遍、走一遍，再决定收不收货。

✅ 它适合什么，不适合什么

适合：目标明确、能拆步骤、结果能验证的任务。做小工具、整理文件、批量改名、写测试、做数据表、把一个想法做成能跑的页面。

不适合：目标模糊、后果不可逆、涉及隐私 / 钱 / 法律的决定。比如「帮我投资」「帮我删掉所有旧文件」「帮我处理客户的身份证照片」。

记住：你当项目经理，它当实习生。它干得越快，你越要看清它干了什么；最后的责任，永远在你这边。

03小测验

1. Agent 和聊天 AI 最大的区别是？

解析：Agent 的关键是「动手」：读写文件、运行命令、看结果、再修正。

2. 让 Agent 干活，下面哪句最靠谱？

解析：目标、边界、验收说清楚，Agent 才知道做到哪算完。

3. Agent 要执行一条你没见过的命令，你应该？

解析：权限越大，越要看清。看不懂就先问，别把「方便」变成「风险」。

04一句话记住这节课

聊天是「说」，
Agent 是「做」。

你当项目经理，它当实习生；目标、边界、验收，一个都不能少。
